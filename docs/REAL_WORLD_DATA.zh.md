# 真实案例与数据

English version: [REAL_WORLD_DATA.md](REAL_WORLD_DATA.md)

挑战要求解决方案围绕真实世界的数据来构建。对我们来说，这意味着四件事：

1. **以一个真实的地方作为测试示例**，其公开数据能显示信息缺口。管道本身与地区无关；第一个测试地区是印度尼西亚的 Samosir。
2. **用当地真实使用的语言写的短信**（印尼语和巴塔克托巴语）。本次构建中这些短信由 Claude 编写；在真实短信上的准确率尚未测量。
3. **真实的设备和渠道限制**：功能机、160 个字符的短信、离线使用。
4. **本次构建中没有真实商户**：每个商户、短信和电话号码都是编造的，并标注为合成数据；村名和地标是真实的。

下面的每个数字都标注为**已测量**（由本仓库中的脚本生成，并注明数据日期）或**尚未测量**。

## 1. OpenStreetMap 中的信息缺口——已测量

脚本：`python scripts/osm_gap.py`（适用于任何地区：`--area-name "<name>" --admin-level <n>`）。输出：`data/real/osm/<area>/`。数据 © OpenStreetMap contributors（ODbL），快照 2026-10-03T19:40Z。

萨摩西县（Samosir）：

| 指标 | 数值 |
|---|---|
| 已列出的餐饮地点（餐馆、咖啡馆、快餐店、美食广场） | 84 |
| 已列出的住宿地点（酒店、民宿、青年旅舍、汽车旅馆、公寓、木屋、营地） | 144 |
| 距主要旅游村 Tuk Tuk 3 公里以内的已列出地点 | 228 个中的 141 个（62%） |
| 有电话或 WhatsApp 号码的已列出地点 | 228 个中的 17 个（7%） |
| 有营业时间的已列出地点 | 228 个中的 12 个（5%） |
| 2 公里内没有已列出的餐饮或住宿地点的村庄点 | 132 个中的 76 个（58%） |
| 5 公里内一个也没有的村庄点 | 132 个中的 41 个（31%） |

如何解读：
- 在 OpenStreetMap 中为零，表示 OpenStreetMap 没有记录。这不表示该村庄没有餐饮或住宿。这份缺失的公开记录，就是本项目要解决的缺口。
- 村庄点是 OpenStreetMap 的 `place=village` 点；它们不是官方村名表。另有 106 个 `place=hamlet` 点已排除。
- 2 公里和 5 公里这两个半径是我们自己定的。Google Maps 和订房网站在 Tuk Tuk 大概列出了更多地点（尚未测量）。

## 4. 测试集——待编写

| 文件 | 内容 | 编写者 |
|---|---|---|
| `eval/host_messages.jsonl` | 15–20 条用该地区语言写的商户短信，每条附带标准答案的商户条目字段 | Claude |
| `eval/traveller_queries.jsonl` | 15 条游客问题，附带应返回的商户条目 | Claude |

规则：
- 每条短信都标注 `"source": "synthetic"` 和 `"author": "claude"`。
- 村名和地标是真实的；商户名称和电话号码是编造的。
- 团队里没有人读得懂印尼语，所以评分只涵盖不读印尼语也能核对的字段：类别、村庄、价格、营业时间。
- 短信和标准答案由同一个作者编写，所以分数只能说明管道可以运行；不能说明在真实短信上的准确率。

## 5. 我们可以和不可以声称什么

- **可以声称（已测量）**：上面的 OpenStreetMap 数字；在我们测试集上的提取准确率；数据包大小；离线搜索在真实手机上可以运行。
- **必须标注为估计**：对游客数量或商户收入的影响。我们的文献笔记没有找到任何因果研究表明，在发展中国家把小商户放到网上会提高其收入。
